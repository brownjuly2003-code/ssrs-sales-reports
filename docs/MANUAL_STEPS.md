# Проверка на SQL Server, в SSRS и Power BI

## Сверка процедур

1. Сгенерируйте CSV командой `python -m ssrs_lab generate` из README. SQL загружает семь файлов в одноимённые таблицы. Ещё два файла, `DimStore.csv` и `DimProduct.csv`, содержат справочники для Power BI.
2. На iMac задача `mssql` запустила SQL Server Developer `2022-CU18-ubuntu-22.04` через Compose с лимитом SQL Server 2048 МиБ. Скопируйте `.env.example` в `.env` и задайте учебный пароль SA. На выделенном стенде выполните `docker compose up -d --wait`, затем `python -m pytest -q -m slow tests/test_mssql.py`. Нужны Python-зависимости проекта, `dev` и Docker Compose в среде тестов.
3. Тесты создают таблицы в учебной базе `RetailLab` с сортировкой UTF-8, загружают синтетические CSV и устанавливают шесть процедур. Проверьте, что прошли все 12 тестов. Они сверяют общие и групповые итоги, остаток для двух магазинов и двух категорий, список дат снимков и пустой результат для даты окончания без снимка, названия регионов, категорий и 64 товаров. Для каскадного параметра проверяются состав, названия и порядок магазинов при выборе одного и двух регионов. Завершите стенд командой `docker compose down`. [Результат на SQL Server 2022](runs/2026-11-18-mssql.md)
4. Для Windows-экземпляра SQL Server 2022 Developer укажите доступную учётной записи службы папку с CSV в копии `sql/02-load.sql`. В отдельной учебной базе `RetailLab` с сортировкой `Latin1_General_100_CI_AS_SC_UTF8` выполните `01-schema.sql`, `02-load.sql` и `03-datasets.sql` через SSMS или sqlcmd. Команда `GO` разделяет пакеты. В Windows нужно проверить права учётной записи службы на этот каталог.

## Постраничный отчёт

После согласованной установки SSRS в штатном режиме настройте базу каталога, адрес веб-службы и портал в Report Server Configuration Manager. Откройте `rdl/SalesStock.rdl` в Report Builder, укажите свой экземпляр SQL Server в источнике `Retail`. Запустите предпросмотр за январь 2026 года. Сверьте общий итог, затем пять выборок из README. При выборе Севера в списке магазинов должны остаться 01–04. В списке «Период по» должны быть только даты с 01.01.2026 по 31.01.2026. Раскройте строку до товара, проверьте подсветку остатка ниже 8 и экспорт PDF с номером страницы. Опубликуйте отчёт в `/Retail/SalesStock`.

При серверной сверке используйте локальные экспорты как эталон сумм. В варианте за 8–18 января проверьте, что в колонтитуле видны названия магазинов 02 и 06. Локальный рендер вывел их идентификаторы. [Пять экспортов](runs/2026-11-19-render.md)

Те же шаги без интерфейса собраны в ручной workflow `.github/workflows/ssrs-windows.yml` (раннер GitHub `windows-2022`, запуск `gh workflow run ssrs-windows.yml`); он ещё не запускался.

## Расписание и письмо

Включите SQL Server Agent. В конфигурации почты SSRS задайте SMTP-сервер и отправителя. В свойствах источника опубликованного отчёта сохраните учётные данные с правом чтения базы и выполнения процедур (логин SQL создаёт `sql/grant_report_reader.sql`, переменные sqlcmd `ReaderLogin` и `ReaderPassword`). Проверьте, что пользователь подписки может создавать подписки и имеет доступ к отчёту.

Сценарий использует SOAP `ReportService2010.CreateSubscription`. Его HTTP-клиент рассчитан на HTTPS с Basic-аутентификацией, разрешённой администратором на сервере. Обычный HTTP принимается только для сервера на той же машине (`localhost`, `127.0.0.1`, `::1`): пароль не уходит в сеть. Задайте `SSRS_SOAP_URL` (например, `https://server.example.invalid/ReportServer/ReportService2010.asmx`), `SSRS_USER` и `SSRS_PASSWORD` в окружении процесса. Для сервера с исключительно Windows-аутентификацией создайте стандартную подписку в портале с теми же параметрами.

Скопируйте `subscription/example.json` за пределы репозитория, выберите согласованный адрес, будущие локальные дату и время запуска, параметры периода и магазинов. `PDF` и `EXCELOPENXML` — поддерживаемые сценарием форматы. Команда `python -m ssrs_lab.subscription <путь-к-копии.json>` создаёт одну новую ежедневную подписку и выводит её идентификатор. Повторный вызов создаст ещё одну подписку. После первого выполнения сверьте статус в портале, наличие вложения в почте и сумму из его таблицы. Пример использует фиксированный учебный период.

## Отчёт Power BI

После генерации CSV откройте `powerbi/Retail.pbip` в Desktop с поддержкой PBIP, TMDL и PBIR. Укажите путь к `data` в параметре Power Query `DataFolder`, включая последний разделитель. Обновите модель. Выберите непрерывный диапазон дат и те же регион, магазины и категории. Сверьте строку итога в матрице с таблицей README и промежуточные строки с `reference.json`. Для расхождения сохраните выборку, уровень группировки, ожидаемое и фактическое значения.

Контрольный запрос мер. После обновления модели откройте вид запросов DAX (DAX query view), вставьте содержимое [`docs/check-measures.dax`](check-measures.dax) целиком и выполните. Запрос вернёт 600 строк: мера, контекст (выборка из README / регион R / магазин S / категория C или товар P), ожидаемое и фактическое значения и `PASS` или `FAIL`. Все строки должны быть `PASS`; отсортируйте по столбцу `Result`, чтобы `FAIL` оказались сверху. В модели данных Excel 21.11.2026 все 600 строк дали `PASS` ([протокол](runs/2026-11-21-dax.md)); совпадение в Desktop покажет, что движок Power BI считает меры так же. Сохраните снимок результата и запишите число строк `PASS`.
