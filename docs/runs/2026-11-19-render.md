# Продажи и остатки: экспорт RDL в PDF и Excel

19 ноября 2026 года библиотека Microsoft ReportViewer в локальном режиме сформировала пять пар PDF и XLSX из исходного `rdl/SalesStock.rdl`. Данные в отчёт передало приложение; источник данных и запрос, записанные в RDL, не исполнялись, сервер SSRS не запускался (подробно — раздел «Как повторить экспорт»). Что все десять экспортов прошли без предупреждений, отмечено автором во время запуска: `Render.exe` печатает число предупреждений в консоль, а консольный вывод не сохранён. В каждом PDF свёрнутый отчёт занял одну страницу A4. В XLSX видны те же итоги, а группы можно раскрыть до товара.

|---|---|---|---:|---:|---:|
| Весь январь | [PDF](2026-11-19-render/all.pdf) | [XLSX](2026-11-19-render/all.xlsx) | 42 | 512 | 73 |

## Что сверено

- В PDF проверены период, номер «Страница 1 из 1», состав регионов и четыре показателя в каждой строке, включая «Всего». При экспорте это делал несохранённый скрипт; после второго аудита то же проверяет `check_render.py` (раздел ниже). Например, за 8–18 января два магазина продали 5 019 единиц на 346 540,82 ₽. Средняя цена составила 69,05 ₽, остаток на 18 января — 2 364 единицы.
- В XLSX все пять общих итогов и 143 строки регионов, магазинов и категорий сверены с независимым архивным расчётом. Для 1 664 товарных строк значения проверены по входному набору отчёта, включая средневзвешенную цену и пустую цену при нулевых продажах. Проверена вложенность строк по магазинам, категориям и товарам. При экспорте значения товарных строк и вложенность проверял несохранённый скрипт; после второго аудита их по полному пути проверяет `check_render.py` (раздел ниже). [Архивный эталон](offline-evidence.zip)
- В 200 товарных строках с остатком меньше 8 ячейка остатка получила заливку `#FFE2C9`. При остатке 8 все 52 ячейки остались белыми. Одна товарная позиция может входить в несколько выборок.
- В колонтитуле локальный ReportViewer вывел числовые идентификаторы выбранных параметров. Например, для двух магазинов напечатано «магазины: 2, 6». Отображение названий параметров и раскрытие строк в веб-портале остаются частью серверной проверки.

## Пересчёт и хранимые файлы (дополнено 19.11.2026)

Скрипт, которым при экспорте проверяли XLSX и PDF, не был закоммичен. Пересчёт перенесён в репозиторий как [scripts/check_render.py](../../scripts/check_render.py). Он заново складывает общий итог и итоги регионов, магазинов и категорий из входных таблиц `ReportRows` в `replay.zip` и сравнивает их с `reference.json` из [архивного эталона](offline-evidence.zip). В XLSX он проверяет строку «Всего», строки регионов, магазинов и категорий (количество, выручка и остаток каждой строки против эталона, по уровням группировки), число товарных строк на уровне группировки товара и заливку `#FFE2C9` только у остатков ниже 8; в PDF — одну страницу размером 595 × 842 пункта (A4), строку «Всего» и «Страница 1 из 1». Значения отдельных товарных строк и средняя цена в этот пересчёт не входили.

Второй аудит 19.11.2026 показал, что такой пересчёт пропускает перестановку названий регионов (числа сравнивались без названия группы), оранжевую заливку не в той ячейке и цветную ячейку при остатке 8, а также чужой PDF под именем выборки и отсутствие `all.pdf`. Скрипт переписан. Теперь он восстанавливает по уровням группировки путь «регион → магазин → категория → товар», сверяет по нему строки групп с эталоном (названия — из справочников генератора) и товарные строки с `replay.zip`, пересчитывает каждую ячейку цены как выручку, делённую на количество (при нулевых продажах ячейка должна быть пустой), требует у товарной строки оранжевую ячейку остатка ниже 8 и белую при 8 и выше и отвергает оранжевую заливку вне ячеек остатка. Оставленный `all.pdf` обязателен; в каждом PDF проверяются одна страница A4, «Страница 1 из 1», период, состав регионов и четыре значения каждой печатной строки. Для отсутствующих PDF выводится «content not checked». Скрипт — шаг задачи CI `offline`, испорченные копии проверяют [тесты](../../tests/test_check_render.py). [Протокол второго аудита](2026-11-19-second-audit.md)

Первая редакция скрипта была запущена на Windows со всеми пятью PDF (вывод — в истории файла `check_render.txt` до второго аудита). Переписанный скрипт запущен на Windows (Python 3.13.7, openpyxl 3.1.5, pypdf 6.16.1) дважды: по закоммиченным файлам и по временной копии папки, куда четыре удалённых PDF восстановлены из коммита `e853c03` (их SHA-256 совпали с таблицей ниже). Оба раза 5 из 5 выборок прошли: 143 строки групп и 1 664 товарные строки совпали по пути, 1 812 ячеек цены пересчитаны, 200 ячеек остатка ниже 8 залиты `#FFE2C9`, 52 ячейки с остатком 8 белые; во втором запуске все пять PDF — одна страница A4 с верными периодом, регионами и значениями. ## Как повторить экспорт

В локальном режиме ReportViewer получает четыре заполненные таблицы и параметры из приложения. Для каждого из пяти сценариев таблицы подготовлены из CSV с seed 39 запросами `Regions`, `Stores`, `Categories` и `ReportRows`. Выполнены SELECT, переведённые из T-SQL в DuckDB по схеме офлайн-проверки проекта. Скрипт подготовки этих входных таблиц не сохранён; их содержимое подтверждает `check_render.py`: итоги таблиц совпадают с независимым эталоном. Контрольные суммы исходных CSV совпали с манифестом, а исполнение процедур на SQL Server проверено отдельным прогоном. [Проверка запросов](../../tests/test_sql_offline.py) · [Протокол SQL Server](2026-11-18-mssql.md)

1. Распакуйте [входные таблицы, параметры и Render.cs](2026-11-19-render/replay.zip) в рабочую папку Windows. Скопируйте туда `SalesStock.rdl` в редакции экспорта: `git show cb28892:rdl/SalesStock.rdl > SalesStock.rdl`, SHA-256 — `93ca9e36fa84bc9294f151525209e0ba3f8bd3ef15f11efac9df0ed52e54207f`. Текущий RDL после второго аудита берёт список дат окончания из набора `SnapshotDates`, которого во входных таблицах нет; с ним этот повтор не проверялся.
2. В ту же папку поместите DLL из `lib/net40` двух пакетов. Для этого прогона использованы [Microsoft ReportViewer WinForms 150.1652.0](https://www.nuget.org/packages/Microsoft.ReportingServices.ReportViewerControl.Winforms/150.1652.0) и [Microsoft.SqlServer.Types 14.0.1016.290](https://www.nuget.org/packages/Microsoft.SqlServer.Types/14.0.1016.290).
3. В PowerShell из этой папки выполните команды ниже. Рядом с каждым JSON появятся его PDF и XLSX.

```powershell
& "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /nologo /r:System.Web.Extensions.dll /r:System.Data.dll /r:Microsoft.ReportViewer.WinForms.dll Render.cs
.\Render.exe .\SalesStock.rdl all.json north.json two_categories.json partial.json first_day.json
```

Повторный запуск из распакованного архива в отдельной папке, по записи автора, сформировал все десять файлов без предупреждений (консольный вывод не сохранён). Построчная сверка подтвердила те же итоги, уровни группировки и цвета ячеек.

Серверная приёмка включает запуск опубликованного отчёта с живым источником, проверку каскада параметров и получение вложения по расписанию. Матрицу Power BI предстоит сверить в Desktop. [Порядок приёмки](../MANUAL_STEPS.md)
