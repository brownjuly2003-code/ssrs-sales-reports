# Продажи и остатки магазинов

Постраничный отчёт SSRS (файл RDL) показывает выручку, проданное количество, средневзвешенную цену и остаток по регионам, магазинам, категориям и товарам. За январь синтетическая сеть продала **55 523 единицы на 3 840 145,58 ₽**. На конец 31 января в магазинах осталось **8 727 единиц**. Эти значения совпали в расчёте по исходным CSV и в хранимой процедуре SQL Server 2022 Developer. [Протокол SQL Server](docs/runs/2026-11-18-mssql.md)

**Что сделано и чего нет.** SQL-часть исполнена на SQL Server 2022 Developer (контейнер Linux в CI) и сверена с независимым расчётом по CSV. Шесть хранимых процедур сверены по-разному: у трёх справочников (`Regions`, `Stores`, `Categories`) списки совпали с CSV; по строкам `ReportRows` совпали 148 итогов пяти выборок (количество, выручка, остаток); у `StockAtDate` совпал остаток одной выборки; `SnapshotDates` вернула 31 дату снимков. Если на дату окончания нет снимка остатков, `ReportRows` возвращает пустой результат вместо нулевого запаса, а в RDL дату окончания можно выбрать только из дат снимков. RDL отрисован в PDF и Excel библиотекой Microsoft ReportViewer **в локальном режиме**: данные в отчёт передало приложение, а источник данных и запрос, записанные в самом RDL, не исполнялись. Сервер SSRS не разворачивался, отчёт не публиковался и не открывался в Report Builder, подписка не отправляла писем, модель Power BI не открывалась в Power BI Desktop. Четыре меры DAX модели вычислены движком модели данных Excel — не Power BI — и в 600 строках контрольного запроса совпали с расчётом Python. Итог одной фразой — в [BRIEF](docs/BRIEF.md).

## Контрольные значения

Один и тот же набор CSV (seed 39) питает хранимые процедуры и модель Power BI. По умолчанию RDL выбирает 1–31 января 2026 года, оба региона, все восемь магазинов и четыре категории. В модели Power BI задайте тот же непрерывный интервал.

| Выборка | Продано, шт. | Выручка, ₽ | Средняя цена, ₽/шт. | Остаток, шт. |
|---|---:|---:|---:|---:|
| Весь январь | 55 523 | 3 840 145,58 | 69,16 | 8 727 |
| Январь, регион Север | 27 724 | 1 917 763,30 | 69,17 | 4 365 |
| Январь, Напитки и Фрукты | 27 678 | 1 904 060,02 | 68,79 | 4 309 |
| 8–18 января, магазины 02 и 06 | 5 019 | 346 540,82 | 69,05 | 2 364 |
| Только 1 января | 1 731 | 119 557,07 | 69,07 | 12 022 |

Средняя цена равна суммарной выручке, делённой на проданное количество. Для остатка отчёт складывает запасы товаров и магазинов на последний выбранный день. В архиве сохранены также промежуточные итоги региона, магазина и категории для всех пяти выборок. [Эталон и контрольные суммы](docs/runs/offline-evidence.zip)

**Дата окончания без снимка.** Остаток — снимок на конец дня; в данных снимки есть за каждый день с 1 по 31 января. До правки 19.11.2026 процедура подставляла ноль вместо отсутствующего снимка (`COALESCE(b.OnHand, 0)`): за 1 января — 1 февраля запрос, переведённый в DuckDB, вернул 512 товарных строк, 55 523 проданные единицы и нулевой остаток. Теперь `ReportRows` при дате окончания без снимка не возвращает строк, отчёт показывает сообщение «Нет строк для выбранных параметров…», а параметр «Период по» предлагает только даты из `SnapshotDates`. Независимый расчёт по CSV в этом случае завершается ошибкой, а не нулём. [Протокол второго аудита](docs/runs/2026-11-19-second-audit.md)

Для каждой выборки PDF и книга Excel получены из исходного RDL библиотекой Microsoft ReportViewer в локальном режиме: таблицы для отчёта подготовило приложение (запросы отчёта, переведённые из T-SQL в диалект DuckDB, над теми же CSV), источник данных и запрос, записанные в RDL, не исполнялись, сервер SSRS не запускался. Экспорт сделан из RDL в редакции коммита `cb28892`, до добавления списка дат снимков и сообщения об отсутствии строк; текущий RDL в ReportViewer не отрисовывался. Все выборки экспорта заканчиваются датами со снимком: 31, 18 и 1 января. В январском PDF видны оба региона и общий итог. В книге можно раскрыть восемь магазинов до категорий и товаров. В репозитории оставлен один PDF как образец, для остальных четырёх в протоколе записаны SHA-256. ## Воспроизведение офлайн

Из корня репозитория в среде Python 3.11+ с зависимостями проекта и группы `dev` выполните команды ниже. Папки `data` и `reports` предназначены для воспроизводимых выходных файлов.

```powershell
$env:PYTHONPATH = 'src'
python -m ssrs_lab generate
python -m ssrs_lab reference
python -m ssrs_lab check-rdl
python -m ssrs_lab check-pbip
python scripts/audit.py --verify-archive docs/runs/offline-evidence.zip
```

Тесты гоняются в CI (Linux): `python -m pytest -q -m "not slow"` — офлайн, `python -m pytest -q -m slow tests/test_mssql.py` — на стенде SQL Server. Пересчёт экспортов ReportViewer по закоммиченным файлам — `python scripts/check_render.py` (`openpyxl` и `pypdf` входят в группу `dev`). В CI это шаг задачи `offline`; то, что пересчёт отвергает испорченные копии книг и PDF, проверяют тесты [test_check_render.py](tests/test_check_render.py).

Команда `python -m ssrs_lab build-pbip --project powerbi` воспроизводит файлы проекта Power BI. Команда `python -m ssrs_lab write-dax-check` пересобирает контрольный запрос DAX [`docs/check-measures.dax`](docs/check-measures.dax). Его прогон в модели данных Excel — `python scripts/excel_dax_check.py --formulas` (только Windows с Excel и pywin32, вне CI). [Отчёт SSRS](rdl/SalesStock.rdl) · [Проект Power BI](powerbi/Retail.pbip)

**Параметр `DataFolder`.** Это параметр Power Query в модели Power BI: каталог, из которого модель читает CSV, с разделителем пути в конце. Значение по умолчанию — `C:/ssrs-sales-reports/data/`, путь-образец для копии репозитория в `C:/ssrs-sales-reports`; оно записано в [expressions.tmdl](powerbi/Retail.SemanticModel/definition/expressions.tmdl) и в константе `DEFAULT_DATA_FOLDER` в [pbip.py](src/ssrs_lab/pbip.py). После клонирования замените его на свой каталог с данными (папку `data` своей копии после `python -m ssrs_lab generate`) одним из способов: в Power BI Desktop — в параметрах Power Query; правкой строки `expression DataFolder` в `expressions.tmdl`; или заменой `DEFAULT_DATA_FOLDER` в `pbip.py` с последующей командой `build-pbip`. Сама `build-pbip` путь не меняет: она записывает значение константы и затирает ручную правку `expressions.tmdl`. Тест воспроизводимости PBIP сравнивает результат генератора с закоммиченными файлами, поэтому в своей копии меняйте константу и файлы вместе.

## Замена Power BI Desktop: движок модели данных Excel

Power BI Desktop в проекте не открывался. Чтобы меры DAX не остались непроверенным текстом, их вычислил движок модели данных Excel (Power Pivot) — тот же язык DAX и те же формулы из TMDL, но другой продукт. Скрипт [`excel_dax_check.py`](scripts/excel_dax_check.py) запускает свой экземпляр Excel через COM, загружает пять CSV запросами Power Query из секций `partition` модели, создаёт шесть связей из `relationships.tmdl`, читает формулы мер из TMDL и выполняет [контрольный запрос](docs/check-measures.dax). 600 строк запроса — четыре меры в 150 ячейках матрицы: общие итоги пяти выборок таблицы выше, 143 промежуточных итога региона, магазина и категории и две товарные ячейки 1 января, с продажами и без них. Эталоны — архивный расчёт pandas по тем же CSV; средняя цена сверяется без округления.

Результат 21.11.2026: 600 из 600 строк PASS, наибольшее расхождение 0. Отрицательный контроль — две намеренно испорченные строки эталона — дал `FAIL` ровно на них. Сверка нашла различие диалектов: движок Excel не знает `COALESCE`, поэтому `Revenue` и `Units Sold` переписаны через `SUM(...) + 0` — в DAX `BLANK() + 0` = 0, и в Power BI результат тот же. [Протокол сверки](docs/runs/2026-11-21-dax.md) · [Построчные результаты](docs/runs/2026-11-21-dax-results.csv)

Не проверены этой заменой: обновление PBIP в Power BI Desktop, страница отчёта с матрицей и срезами, её вид и снимки экрана. Готовый запрос для вида запросов DAX в Desktop — в [шагах проверки](docs/MANUAL_STEPS.md).

## Риски

- **Совместимость расписания подписки с SSRS не проверялась.** Код `CreateSubscription` проверен только на транспортном двойнике: он возвращает заранее заданный ответ, а тест проверяет состав запроса по ожиданиям самого проекта, не по схеме сервера. Элемент `ScheduleDefinition` внутри `MatchData` записан без пространства имён; какое пространство имён и какую схему этого XML ожидает сервер, в проекте не установлено. Проверить можно только на развёрнутом SSRS.
- В колонтитуле локального экспорта напечатаны идентификаторы параметров («магазины: 2, 6»), а не названия; как сервер выведет подписи, не проверено.
- Защита от нулевого запаса срабатывает, когда на дату окончания нет ни одной строки снимка. Если снимок на дату есть, но в нём не хватает отдельных магазинов или товаров, для них отчёт по-прежнему покажет остаток 0. В данных проекта все 31 снимок полные: 15 872 строки = 31 × 8 × 64.
- Меры DAX вычислены движком модели данных Excel, а не Power BI. Язык и формулы те же, но движки разных продуктов поддерживают разный набор функций: `COALESCE` Excel не знает, и меры пришлось переписать. Поведение в Power BI выведено из документированной семантики DAX, а не измерено.
- Сохранённые PDF и книги Excel получены из RDL до правки параметра даты. Текущий RDL с набором `SnapshotDates` и сообщением при пустом результате ни ReportViewer, ни сервер SSRS не отрисовывали.

## Не сделано

Для выполнения обещания целиком остаются шаги, которые требуют Windows с SSRS и Power BI Desktop. [Порядок проверки](docs/MANUAL_STEPS.md)

- Развернуть SSRS, опубликовать RDL и выполнить его с собственным источником данных и запросом; проверить каскад параметров, переключатели групп и подписи параметров в колонтитуле.

- Настроить подписку через SQL Server Agent с отправкой почты (SMTP) и получить вложение по расписанию. Стандартная подписка задаёт один набор параметров и адресатов, управляемая данными получает параметры доставки для каждой строки запроса. Для расписания нужны SQL Server Agent, настроенный SMTP, адрес отправителя и сохранённые на сервере учётные данные источника.
- Открыть модель PBIP в Power BI Desktop, обновить её, выполнить контрольный запрос `docs/check-measures.dax` и сверить матрицу с таблицей выше. Меры DAX вычислены только в модели данных Excel; в Power BI они не исполнялись.
